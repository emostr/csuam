# ЦСУАМ "Архивли"

Цифровая система управления архивными материалами школы "Архивли"

Платформа для долгосрочного хранения, систематизации и учёта школьных материалов: наград, фотографий, видео, библиотеки и архивных документов.

## Стек

- Фронтенд: TypeScript 7, Vue 3, TailwindCSS, sweetalert2-neutral, Chart.js (на основе собственного шаблона NightingaleUI-template-Vue — https://github.com/emostr/NightingaleUI-template-Vue)
- Бэкенд: Go, Chi, sqlc (go-sql-driver/mysql)
- СУБД: MariaDB
- Хранилище файлов: S3-совместимое (MinIO)
- Сервер: Caddy, Docker

## Возможности

- Пять категорий материалов: награды, фотографии, видео, библиотека, документы;
- Многофункциональный поиск: по ключевым словам, времени происхождения, категориям;
- Аналитика: всего единиц, соотношение по категориям, динамика добавления;
- Карточка экспоната: просмотр файлов прямо на портале, состояние, местонахождение физического экземпляра, время происхождения и добавления;
- Несколько файлов на один экспонат: файлы переключаются вкладками в просмотрщике, их можно добавлять и удалять после создания карточки;
- QR-код со ссылкой на карточку, которую можно распечатать и наклеить на физический экземпляр;
- Экспорт/импорт карточек в JSON и XML;
- Встроенный текстовый редактор: WYSIWYG и Markdown; такие документы хранятся в БД;
- Прокат: учёт выданных книг, срок возврата, уведомление о просрочке, архив возвратов;
- Разделение ролей:
  - Завуч — полный доступ, включая управление пользователями;
  - Библиотекарь — полный доступ, кроме "Документов" (открываются избирательно по решению завуча), может вести прокат и модерацию;
  - Учитель — добавляет материалы (премодерация).

## Поддерживаемые форматы файлов

PDF, DOC, DOCX, PPT, PPTX, ODT, ODP, PNG, JPG, GIF, SVG, BMP, WEBP, MP4, MP3, WAV, WMV, WEBM, HTML, MD.

Изображения, видео, аудио, PDF, HTML и Markdown-файлы открываются прямо на платформе. Файлы DOC(X), PPT(X), ODT и ODP предлагаются к скачиванию.

К одному экспонату можно прикрепить любое количество файлов (суммарно до 512 МБ на запрос). Список файлов редактируется в форме экспоната: новые файлы и пометки на удаление применяются при сохранении.

## Запуск в Docker

```bash
cp .env.example .env
docker compose up -d --build
```

Не забудьте подставить свои значения переменных в .env. 

Платформа будет доступна по адресу http://localhost:8000. Изменить порт можно через переменную окружения "HTTP_PORT", а интерфейс публикации — через "HTTP_BIND" (по умолчанию 127.0.0.1, то есть снаружи платформа доступна только через Caddy).

При первом запуске автоматически применяются миграции и создаются пользователи "zavuch" (завуч), "librarian" (библиотекарь) и "teacher" (учитель). Пароли по умолчанию берутся из переменных окружения SEED_HEAD_TEACHER_PASSWORD, SEED_LIBRARIAN_PASSWORD и SEED_TEACHER_PASSWORD. После первого входа требуется смена пароля в настройках.

## Запуск в проде

Развёртывание на Debian или Ubuntu полностью автоматизировано скриптом "deploy.sh":

```bash
cp deploy.conf.example deploy.conf
nano deploy.conf
sudo ./deploy.sh
```

Скрипт устанавливает Docker и Caddy из официальных репозиториев, при необходимости отключает nginx и certbot (конфигурация сохраняется в резервную копию), генерирует .env со случайными паролями, собирает и запускает контейнеры, настраивает Caddy и получает сертификат Let's Encrypt. Повторный запуск обновляет платформу: скрипт идемпотентен, ранее сгенерированные пароли сохраняются, а перед обновлением снимается дамп базы.

Полезные ключи:

- "sudo ./deploy.sh --check" — проверить конфигурацию, DNS и занятость портов, ничего не меняя;
- "sudo ./deploy.sh --skip-packages" — не трогать apt-пакеты;
- "sudo ./deploy.sh --config /путь/deploy.conf" — другой файл конфигурации.

Все параметры (домен, почта для сертификата, режим TLS, каталог установки, пароли, фаервол, резервные копии) описаны в deploy.conf.example.

Сертификаты выпускает и продлевает сам Caddy, certbot не нужен. Хостовая конфигурация генерируется в /etc/caddy/conf.d/csuam.caddy, её образец — caddy/csuam.caddy.example.

## Страницы ошибок

Страницы 401, 403, 500 и 502 лежат в frontend/public/errors. Их отдают оба уровня: контейнер фронтенда — при ошибках приложения, хостовой Caddy — при своих (например, когда стек не отвечает; deploy.sh копирует страницы в /var/www/csuam-errors). Прочие ошибки 5xx показывают страницу 500. Ответы API остаются в JSON: HTML-страница подставляется только тогда, когда запрос пришёл из адресной строки браузера (заголовок Accept содержит text/html), поэтому fetch-клиент продолжает получать {"error": "…"}. Исходный код ответа сохраняется.

## Разработка

Бэкенд (Go 1.25+):

```bash
cd backend
go mod tidy
go run ./cmd/server
```

Фронтенд (Node 20+):

```bash
cd frontend
npm install
npm run dev
```

Дев-сервер Vite проксирует /api на localhost:8080. MariaDB и MinIO нужно запускать из compose: docker compose up -d mariadb minio

SQL-запросы описаны в backend/queries/ в формате sqlc, конфиг backend/sqlc.yaml, схема в backend/internal/migrate/sql/. Миграции применяются автоматически при старте.
